# EVENG2 · ORBITAL HUD

为 Even Realities G2 打造的轻量级 HUD：手机端采用黑白灰 terminal 风格标签页，支持深色／浅色切换；眼镜端采用简洁的单色信息卡片。

真机语音和定位功能要求 Even Realities App 2.2.10 或更新版本，并由用户在应用中授予相应权限。

## 开发启动

```bash
npm install
npm run dev
```

本机预览眼镜画面：

```bash
npm run simulate
```

连接真机时，在电脑与手机处于同一 Wi-Fi 网络的情况下运行：

```bash
npx evenhub qr --url http://<电脑局域网IP>:5173
```

使用 Even Realities 手机应用的 Prototype Mode 扫描二维码。

公开 SDK 未开放系统 Display off 控制，因此这里的息屏为黑屏待机，不等同于硬件断电；保留页面才能收到长按唤醒。息屏期间停止显示与天气定时刷新。应用的 Dashboard 菜单无法绕过息屏或最小化的恢复手势；退出应用仍可使用系统层入口。参考官方[上下文菜单说明](https://hub.evenrealities.com/docs/build/contextual-menu)。

右侧主页的图标通过一张窄图片列显示，栏目名称、右侧选择标记、分隔横线及概要使用 SDK 原生文字。四项文字维持相同亮度，滑动时仅更改 `<` / `-` 标记和概要。AI 概要优先保留最近一轮提问，中文交由眼镜原生字库显示。Information 每次进入时请求一次英文一言，完整显示；停留期间不自动刷新、不播放打字和删除动画，离开时取消未完成请求。

主界面使用四块图像和八个原生文字容器，共十二个容器。空白外框文字容器接收手势，四个栏目文字行只包含栏目名称；独立原生文字列包含四行选择标记，原生横线与栏目概要各用一个文字容器。另有一张窄图像容器同时显示四个图标。所有类型的容器使用独立编号，创建和重建前检查编号是否重复。图像用于像素时钟、天气、电池和菜单图标列，进入或返回首页仍逐张发送；切换栏目时只更新标记列和概要，不发送图片。聊天和待办详情使用原生边框与文字，只发送一个 20×20 标题图标。Information 与天气数据、标题、外框继续原生显示；0.1.23 起，这些页面的精确 1px 分隔线与图标共用稀疏图像区域，避开真机不显示短边为 1px 的原生边框容器的问题。天气地图、预报符号、范围图、风向图标和月相图等内容也保留为图像。未变化的图块和文字不重复上传。编码后的图片使用有数量上限的缓存，重新访问同一画面时不重复编码。图像保持原分辨率与 16 级灰度，支持 CompressionStream 的 WebView 使用 4-bit 灰度 PNG，旧版保留 Canvas PNG 路径。

如需保留手绘图标，可在构建时设置 `VITE_HOME_MENU_RENDERER=bitmap`。此备用模式将图标、文字和横线合成为一张 262×114 图片，预先缓存四种选中状态，每次切换只发送同一张完整菜单图片，不会把图标与文字分开发送。默认使用原生菜单图标。

刷新只保留正在发送的一帧和最新请求。连续操作时合并中间状态，新输入到达后取消旧画面尚未发送的图块；图片仍逐张发送，避免图片通道冲突。控制台 `HUD image transport` 记录图片数、像素面积、PNG 字节数、编码耗时、桥接发送耗时和是否被新画面取代，用于真机对比，不代表眼镜显示帧率。原因与参考实现见 [渲染性能说明](docs/rendering-performance.md)。

天气详情没有翻页动画或风线刷新循环，风图使用固定相位绘制静态线条和周围地图轮廓。运行 `node scripts/check-home-navigation.mjs` 检查首页输入；`node scripts/check-details.mjs` 检查聊天顺序和间隔、长回复的完整滑动浏览、新对话归档、双击保护、迟到回复隔离，以及天气和一言；`node scripts/check-hud-rendering.mjs` 检查图片编码及容器图像布局；`node scripts/check-hud-transport.mjs` 用慢速桥接模拟检查刷新合并、过时图块取消和文字优先。

字体文件为 `src/assets/dashboard-native.g2font.json`，包含 660 个捕获字形（含信息栏与空待办提示所需汉字），`@evenrealities/pretext` 提供官方字宽与字距。未覆盖的文字（例如其他中文城市名或待办内容）交给 SDK 原生文字显示，涉及这些卡片时直接切换。普通详情和 AI 对话静止时使用 SDK 原生文字，天气图表使用相同来源的位图字形。字库与模拟器原始字形一致，但官方说明模拟器字体渲染可能与硬件不同，不能保证与真机系统 Dashboard 逐像素一致。来源、格式与重新导出方法见 `src/assets/README.md`。

左侧保留像素时钟、日期与天气样式，小天气组件使用较暗的细连线像素字，统一字号、列对齐与居中布局，天气图标统一使用 16×16 细线图标区域；右上角仅显示电池图标。首页长按息屏、长按恢复；双击最小化、双击恢复。

HUD 仅在长按期间启用眼镜麦克风，语音最长录制 25 秒。天气默认优先读取手机的高精度 GPS 位置，并以该位置为天气和风图中心；定位不可用时使用设置中保存的城市。可在设置中关闭 GPS，或更换备用城市和温度单位。

## 配置 AI 与联网搜索

默认使用现有的 OpenAI 云端接口和 `gpt-4o-mini`。打开右上角设置面板，粘贴完整有效的 OpenAI API Key，点击 **Check key** 即可检查连接。地址、模型、relay 收在 **Advanced connection**，沿用默认配置时不必填写。

程序会清理 Key 粘贴时混入的 `Authorization: Bearer`、外层引号、换行与不可见空格；不会生成或修复无效的 Key。若官方返回 `401 / invalid_api_key`，应用会直接打开设置并定位 Key 输入框，请在 [OpenAI API Keys](https://platform.openai.com/api-keys) 页面新建有效 Key 后重新粘贴。验证读取模型列表，不生成回复；未自动替用户使用真实 Key 发起计费聊天。

需要自定义时填写：

- **聊天 API 地址**：OpenAI Chat Completions 兼容地址，默认 `https://api.openai.com/v1/chat/completions`。填完整接口地址，或填 `/v1` 这样的 API 根地址。
- **模型名称**：默认 `gpt-4o-mini`。
- **API Key**：聊天服务密钥。
- **AI relay URL**：可选。开发模式留空，OpenAI/Tavily 自动经电脑转发；正式安装版可填你自己部署的 HTTPS relay 地址。部署方式见 [relay/README.md](relay/README.md)。
- **语音转写地址 / 模型 / Key**：默认使用 OpenAI `audio/transcriptions` 和 `whisper-1`；转写 Key 留空时沿用聊天 Key。
- **联网搜索**：使用 OpenAI 官方 API 时，开启 **Enable web search**，将 **Tavily Search API Key** 留空即可使用 OpenAI 内置搜索，复用聊天 Key，无需额外搜索 Key。调用 Responses API 的 `web_search`，由所选模型判断是否搜索；需要模型支持该工具、账号拥有相应权限和额度，搜索按 OpenAI API 规则计费。填入 Tavily Key 则继续使用 Tavily：先搜索，再交给聊天模型；其他兼容服务仍需 Tavily Key。搜索关闭时保持原来的聊天路径。

密钥和对话仅存储在当前手机的 Even Hub 本地存储中。聊天、搜索和语音数据会发送给设置中的服务商；联网搜索关闭时不会调用搜索工具。G2 没有扬声器，AI 回复会显示在眼镜和手机屏幕上。OpenAI 搜索返回的引用在手机端可点击，眼镜显示紧凑引用标记。只有接口报告完成搜索调用才显示“web searched”，不会把开启开关等同于实际完成搜索。原生搜索设置 `store: false`，不会静默切换模型、失败后改用无搜索答案或自动重试计费请求。接口说明见 [OpenAI Web search](https://developers.openai.com/api/docs/guides/tools-web-search)。

AI 沿用原生 `fetch` 和现有开发服务器，无新增运行时依赖或本地模型。空闲时没有 AI 轮询；每次发送最多携带最近 8 条消息、合计 6000 字符，当前问题保持完整（最长 4000 字符）。Tavily 搜索最多 3 条结果，送给模型的搜索上下文不超过 3000 字符；OpenAI 内置搜索的结果由服务端工具提供，不适用 Tavily 的三条限制。回复最多 384 tokens。OpenAI 普通聊天使用 `max_completion_tokens`，内置搜索使用 Responses 的 `max_output_tokens`，其他兼容服务使用 `max_tokens`；该上限也包含推理 token，使用推理模型时可能需要提高上限，默认模型仍为 `gpt-4o-mini`。

## 天气与联网权限

天气使用 [Open-Meteo](https://open-meteo.com/) 公共地理编码和[预报接口](https://open-meteo.com/en/docs)，不需要 API Key；默认每 30 分钟刷新一次，也可手动刷新。

打开天气详情时，读取 [OpenFreeMap](https://openfreemap.org/) 的 OpenStreetMap / OpenMapTiles 矢量地图，只描绘真实湖岸、水道、主要道路和行政边界轮廓，不填充地理区域。附近地名缩小到原字体约 58%。采用 Web Mercator 区域视图，北向朝上；中心圆圈显示选定地点的当前风速（km/h），下方为地点名，角落提供随纬度计算的比例尺。地图与预报风场使用相同地理范围：九个采样坐标覆盖地图视图，按双线性插值生成风线。风场仍为模型预报，不是雷达或实时观测。

晴/云/雨装饰背景已移除，当前风线使用固定相位绘制，不运行连续风场动画。天气与风场按地点缓存 30 分钟；只在进入天气详情时加载当前小视口至多四张瓦片，内存缓存复用，不批量下载离线地图。地图、风场、空气质量分别到达后请求刷新，短时间内到达的更新由共享刷新任务合并。加载失败明确显示 Map unavailable / Wind unavailable，稍后重新进入可重试；显示地图无需额外 API Key。

地图来源标注保留在手机端，眼镜天气页不显示来源脚注；地图数据许可见 `THIRD_PARTY_NOTICES.md`。

空气质量使用 [Open-Meteo / CAMS](https://open-meteo.com/en/docs/air-quality-api) 的模型数据。天气与空气质量数据遵循 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。SunCalc 的 BSD 许可见 `THIRD_PARTY_NOTICES.md`。

Information 使用 [一言语句接口](https://developer.hitokoto.cn/sentence/) 的 `https://v1.hitokoto.cn/?lang=en&max_length=90`。官方文档列出 `hitokoto` 返回字段，但未列出 `lang` 参数；若接口返回非英文、字库不支持的字符或请求失败，当前轮次显示内置英文句子，下一轮继续请求。每轮只请求一次。

Even Hub 要求在 `app.json` 的 `network.whitelist` 中列出请求域名。项目已加入 Open-Meteo（含空气质量域名）、OpenFreeMap 地图瓦片、Hitokoto、OpenAI 和 Tavily。若使用自定义聊天或转写服务：

1. 将服务的 HTTPS origin 加入 `app.json` 中 `network` 权限的 `whitelist`。
2. 确认服务端允许 Even Hub WebView 的 CORS 请求和 OPTIONS 预检。
3. 更改权限白名单后重新打包并安装应用。

开发模式的 OpenAI 聊天、转写、连接检查和 Tavily 搜索请求会自动经当前 Vite 服务器转发；自定义 API 域名继续直接请求。正式 `.ehpk` 默认直接连接，也可使用设置中的 HTTPS relay（或 `VITE_AI_RELAY_URL` 构建默认值），并将真实 relay origin 加入白名单。代理部署说明见 [relay/README.md](relay/README.md)。

设置中的 **Check key** 读取模型列表，不生成回复。错误显示真实 HTTP 状态和服务端说明；模型列表权限不足时可能返回 403，即使聊天权限存在。`Failed to fetch` 本身无法区分 CORS、DNS、网络与 WebView 权限，不能仅凭此错误断定 CORS。relay 保留上游状态码，连接失败时区分 DNS（502）、其他连接错误（502）和超时（504）。

## 构建与打包

```bash
npm run build
npm run pack
```

`npm run pack` 会构建应用并生成 `.ehpk`。正式发布前请把 `app.json` 的 `package_id` 改为你自己的唯一 ID，并检查权限说明、网络域名和隐私告知。

每次更新都递增补丁版本号，并同步 `app.json`、`package.json` 与 `package-lock.json`；安装包文件名包含对应版本。当前版本为 0.1.40。

## 项目结构

```text
.
├── app.json          # Even Hub 清单、网络白名单和设备权限
├── index.html        # 手机端仪表盘、对话面板和设置面板
├── src/main.ts       # SDK 桥接、HUD 页面、天气、AI、语音录制
├── src/dashboard-clock.ts # 3×3 九宫格数字时钟
├── src/weather-data.ts # 10 日预报、九点风场、空气质量和月相
├── src/weather-scenes.ts # 固定天气分页、流动风线与细线图表
├── src/map-viewport.ts # 地图与风场共用的地理投影
├── src/wind-basemap.ts # 真实矢量地图、地理轮廓与地名
├── src/map-text.ts # 地图小字号地名字形
├── src/hud-motion.ts  # 卡片展开/缩回与无损帧编码
├── src/style.css     # 手机端 HUD 视觉样式
└── vite.config.ts    # Vite 开发服务器与构建配置
```

G2 的双眼显示画布为 `576 × 288`，绿色单色、没有背景填充或扬声器。眼镜 HUD 以高对比度文字和细边框建立层级；手机端负责输入和详细设置。
