# LeetCode · 0.1.31 每日一题

**当前版本恢复 LeetCode 国际站英文每日一题。** 首页第五项为 **LeetCode daily**，概要显示题号与难度（例如 `#2089 / Easy`），主页上下首尾循环。

题目从原有只读接口加载，使用每日题缓存，不读取 #94 测试缓存。正文、题尾统计、单击图片页、多图切换和点阵增强保持原有逻辑；手机显示原图。测试素材留作源码参考，不再被主程序引用或打入正式安装包。动态图片仍受图床可用性与跨域权限影响，详见下方“图片”。

## 图片页与滑动

- 正文图片位置只显示 `[Image 1 - tap to view]` 等一行提示，正文不自动加载或插入大图。
- 在题目页任意位置单击，打开离当前阅读位置最近的一张图；图片页显示 `Image 1 of 2` 等计数，整张图按比例放入 514×189 的阅读区域，输出图片不超过 500×189。
- 图片页上下滑动循环切图；再次单击回到正文，保留原阅读行数；双击仍直接回主页。单击等待 300ms 区分双击，避免双击的第一下误开图片页。
- LeetCode 正文与图片页不再经过天气的 550ms 最小间隔或渲染提交锁。独立滑动立即修改状态；100ms 内连续同向事件视为同一事件串，忽略重复事件也更新时间，防止连续事件自动多翻。反向滑动立即接受；正文每次移动两行，图片每次换一张。SDK 未提供滑动手势 ID，重复事件按此短间隔合并，真机手感可继续调整。
- 单张图片不会切换；无图题目单击不进入图片页。图片加载失败保留提示，可单击回正文，再次打开重试。

## 0.1.29 点阵处理

所有经 `loadProblemImage` 获取的题目图片（联网、代理、内置）都按相同顺序处理：

1. 保持比例缩放到不超过 500×189，然后读取灰度，避免点阵生成后缩放破坏亮点。
2. 估计四周背景亮度并移除底色；浅底深色图反相，深底亮色图保留发光方向。
3. 按 0.5% / 99.5% 分位拉伸有效对比度，小幅提亮中间调；稀疏轴线保留，防止被分位截掉。
4. 使用蛇形 Floyd–Steinberg 误差扩散，输出仅 0 / 255 两种像素。原来依赖微弱灰阶的区域改由全亮点的密度表示；纯背景和实亮线条固定，减少背景杂点。
5. 点阵结果缓存；滚动按整数像素裁切，不重新抖动、不随机采样，不改变原生文字、图像容器数量和串行传输规则。

这是一种牺牲空间细节来表现灰度的方法，不能完美保留原图颜色或全部细节，可能产生颗粒感；实际可视性仍以真机为准。算法说明参见 [ImageMagick dithering](https://imagemagick.org/command-line-options/#dither)。原图文件保持不变。

`src/leetcode-image-test.ts` 已停用且不被生产入口引用；原独立测试缓存不会覆盖每日题缓存。

## 每日题模式

首页第五项 **LeetCode daily**：单击进入；上下滑动每次移动两行，阅读完整题面；标题固定，底部显示日期与行数进度；双击返回首页。没有代码输入、提交或题解。沿用详情页原有长按语音操作。

使用 **LeetCode 国际站英文每日题**。编号使用公开 `questionFrontendId`，不是内部数据库 ID。题号与题名显示在固定标题栏，日期保留在底部，正文直接从题意开始。段落和示例之间保留一个空行；Example、Constraints 标题后不加空行，约束条目连续显示。正文包含示例、输入输出、解释、约束与进阶问题；HTML 转为安全文字，保留上下标含义（如 `10^5`、`a_i`）、列表与表格。

题尾展示 Difficulty、Accepted submissions、Total submissions、Acceptance rate。通过次数和总提交次数来自官方 `stats.totalAcceptedRaw` / `totalSubmissionRaw`，不是去重人数；默认公开每日题接口未包含次数时，只读查询匹配的 `/problem/{slug}` 补全。按 slug 和题号核对，统计不可用时明确显示 Unavailable，不编造数值。缓存保存统计，升级旧缓存会重新请求补全；只更新统计时保持阅读位置。

G2 SDK 0.0.16 原生文字容器没有字体、字号或字重选择；本版保持原生文字。使用不同字体需要自行将文字绘制为图片，无法保证有原生文字同样的更新速度。手机端字体与眼镜端独立。

## 数据与缓存

- 开发版使用现有 Vite relay 的只读 `GET /leetcode/daily`，查询官方 `activeDailyCodingChallengeQuestion`。
- 正式安装版读取支持跨域的公开 [noworneverev/leetcode-api /daily](https://github.com/noworneverev/leetcode-api#quick-start)，失败时尝试独立的 [alfa-leetcode-api /daily](https://github.com/alfaarghya/alfa-leetcode-api#endpoints-)；配置现有 HTTPS relay 时优先复用该服务，不发送 AI Key、登录信息或 Cookie。旧版 relay 没有路由时会继续尝试公开接口。检查中确实触发过 Alfa 429，独立备用来源和本地缓存用于处理这种情况。
- 不需要 LeetCode 账号、AI Key 或搜索 API。公共服务有可用性和限流限制；失败会显示提示，单击重试。
- 最近一次成功的完整题面保存在手机本地；当日缓存 15 分钟内复用。进入时日期变化会重新获取，日期按国际站 UTC 每日题计算。接口返回旧日期时明确标记缓存题目，不冒充当天题。正在阅读时不定时替换内容，重新进入或手机刷新可更新。
- 手机仪表盘可刷新、展开只读题面或打开原题。

## 图片

正文图片仅保留一行位置引用，延迟加载不会移动正文。打开图片页时才获取当前图片，并按比例缩放到最多 500×189、进行点阵增强；内存最多保留十幅。

官方图床实测不返回跨域头，因此**正式安装版直接请求图片可能失败**。已更新的本地/自有 relay 提供限于官方 `/uploads/` 图床的只读图片转发，可正常转换；无可用转发时显示 `Image unavailable - see phone`，正文可继续阅读。手机只读页面直接显示原图，并提供原题链接。不能转换的 SVG/外部图片保留提示。

所有眼镜图片按 SDK 上限拆成最多四个 288×144 以内的容器，串行传输。正文始终使用原生文字，每次最多七行、每行最多 128 UTF-8 字节；只有空白外框接收滑动，标题不会跟随原生滚动。模拟器不能替代真机显示检查。
